## 可以先试什么

以下是本库待实践建议：为一个具体功能分别写清“能演示”“通过规定测试”“允许正式交付”的标准。保留版本、环境、真实客户端、测试结果和失败记录；明确支持范围、发布判断责任与回滚方式，再做一次有范围的验证，不凭 Agent 汇报“完成”跳过验收。

先核查最关键且尚无证据的一项，不要求所有项目机械复制相同清单。正式交付授权与执行仍按用户实际流程决定。

## 缺失证据与待验证

- 当前没有用户项目的原型、需求验收与生产部署记录，不能替用户作上线结论。
- R0025 没有可供本库重放的测试报告或源码版本；功能正确性、性能、数据一致性、故障恢复、权限和兼容性仍需实际依据。
- 应分别记录生成初版、调试、稳定化、审查和维护的时间、人工投入与费用，不能用初版小时数或 API 标价估算替代交付总成本。
- 测试通过不覆盖未表达的业务约束；持续运行也需明确负载、错误与观测范围，不能直接推出可靠性保证。
