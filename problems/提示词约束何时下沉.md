# 反复提醒 Agent 仍犯错，哪些约束该下沉到工具或框架？

[← 问题索引](README.md)

检索词：提示词太长、重复犯错、mock 还原、硬门禁、代理指标、框架、lint。

## 先看什么

先读 [R0011](../resources/R0011/README.md) 第一部分：自动还原取消一类错误；运行反馈应可核验；不准确的规则可能导致反向优化。

补充 [R0007](../resources/R0007/README.md) 的架构与静态检查层次，以及 [R0003](../resources/R0003/README.md) 的精简项目说明结构。

## 可以先试什么

以下为据材料归纳的待实践建议：选一类反复出现的错误，区分稳定行为约束与临时补丁，核实是否有准确、外部可取得的检测信号；先用实际例子测误报，再决定是工具、框架能力、阻断检查还是提醒。

## 还缺什么

没有用户项目误报、成本和可绕过性数据，不能仅凭反复犯错就增加硬门禁，更不必为每条提示词自建 runtime。

补充：[R0021：大仓 Harness 实战](../resources/R0021/README.md)，第 2.1、6 章补可判定规则下沉、软硬门禁与开发前后基线；原文阈值有差异，不能照抄为统一门禁。
