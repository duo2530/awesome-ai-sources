# 怎样让 Agent 自动处理反馈，又能在做错前停下来？

[← 问题索引](README.md) · [标签](../tags/README.md)

检索词：自动化、分诊、复现、修复、证据、停止条件、人工瓶颈。

## 当前认识

截至 2026-11-15，本库材料支持以下判断；每条都受文末证据缺口限制。

1. **闭环的最小完整形态是四段：授权 → 执行 → 独立验证 → 人工门或停机。** 缺任何一段都会退化成“看起来自动”。依据：[R0026](../resources/R0026/README.md) 把 Source、Trigger、Ticket、Mandate 与执行分开，[R0029](../resources/R0029/README.md) 走 Issue → PR → 独立评审 → 合并，[R0028](../resources/R0028/README.md) 用配额判定与人工门。性质：本库归纳。
2. **“能停下来”比“能继续”更值得先设计。** R0029 的 `ai-blocked`、R0028 的“该等、该停”档、[R0005](../resources/R0005/README.md) 的停线条件，都选择把不可恢复错误交给人，而不是静默重试。性质：多份项目自述方向一致，但都没有失败率或回滚率数据。
3. **独立验证不能由执行者自己兼。** R0029 的独立评审会话、[R0009](../resources/R0009/README.md) 的独立自检、[R0017](../resources/R0017/README.md) 的独立复核，是三种不同粒度的同一主张。性质：本库归纳。
4. **合并门禁是否真的强制，是所有材料的共同证据缺口。** 项目普遍声明“AI 不合并”，但都是 README 自述；分支保护是否配置、runner 权限能否绕过，本库一份都没核验。
5. **人工确认的位置存在真实分歧，且取决于风险与修正成本。** [R0021](../resources/R0021/README.md) 选关键节点人工确认、异常熔断；[R0022](../resources/R0022/README.md) 选少阻塞、靠后续修正。适用条件不同（跨仓业务大仓 / 高吞吐新建产品），不能合并成一条“最佳实践”。

## 观点差异与适用条件

以下为本库对材料的比较，不是统一标准；优先回查各资料入口的原文依据。

| 取舍 | 依据 | 适用条件与边界 |
|---|---|---|
| 关键节点人工确认、异常熔断 | [R0021 原文依据](../resources/R0021/README.md#关键摘要的原文依据)，5.1—5.2 | 跨子仓库业务大仓的作者方案；不能把“半自动唯一稳定”当作通用事实 |
| 较少阻塞门禁、更多 Agent 审查与后续修正 | [R0022 原文依据](../resources/R0022/README.md#关键摘要的原文依据)，Throughput changes the merge philosophy | 作者的新建内部产品，高吞吐且修正便宜；不据此取消风险较高变更的人审 |
| 用阶段证据与停止条件控制循环 | [R0005](../resources/R0005/README.md)，分诊、复现、修复 | 与上述两种取舍互补；即便自动执行也要有可见失败和结束路径 |

共同点是反馈、证据和恢复能力，人工介入位置存在真实差异。本库没有对照数据判断哪一种对用户项目更优。

## 可以先试什么

以下为据材料归纳的待实践建议：先选一类反馈，定义输入、证据和“不继续”的条件，手动完成一轮后再讨论触发器；非缺陷、无法复现与风险过大都应能结束本轮。

## 还缺什么

缺少用户项目中的权限、成本、停止与回滚实现。先补一类任务的完成时间、人工介入次数、逃逸缺陷、回滚耗时与总成本，再比较门禁选择；PR 数量不能单独证明交付质量。文章的通知和自动继续规则不构成本库授权；没有配置任何自动化。

## 门禁与无人值守参考

[R0028：loopx](../resources/R0028/README.md)：把“该继续、该问、该等、该停”做成配额判定，并把 owner、安全、发布、私有数据分成不同的门；README 明确它不是自主生产控制器。安全回退不得绕过 gate 是文档规则，实现未读。

[R0029：orbi](../resources/R0029/README.md)：Issue 打 `ai-ready` 后走实现、PR、独立评审、合并与发布；不可恢复错误标 `ai-blocked`，不静默重试。两篇的门禁都由项目自述，均未在用户项目验证。

补充：[R0030：Your coding agents made you a manager](../resources/R0030/README.md)：无人值守前先答五问——完成定义、自验证手段、边界、护栏（轮次与花费上限）、产出位置与谁批准非可逆动作；并建议先在三个文件上试点、观察前几次运行再放开。

补充：[R0031](../resources/R0031/README.md)：merge queue 在 main 上重跑、feature flag 先内部后公开、latest/stable 分渠道、一键回滚；把 revert 率与事故率当护栏，防止“省了评审时间只是把成本挪到修复”。

补充：[R0033](../resources/R0033/README.md)：同一检查失败三轮后交人；commit gate 先 observe 记录本会拦下的改动，再进 enforce，并允许 commit message 说明理由绕过；变更不能修改评判自己的检查，评审结果绑定到具体 commit。
