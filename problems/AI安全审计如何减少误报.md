# 怎样让 AI 审计代码，又避免把猜测当漏洞？

检索词：误报、候选反证、独立复核、信任边界、覆盖缺口、安全报告。

## 先看什么

[R0017：Cloudflare security-audit-skill](../resources/R0017/README.md)：先读 README 六阶段，再看 SKILL.md 的 Core principles，以及 VALIDATION-AND-REPORTING.md 的三种结论契约。

重点区分：confirmed 需要完整源代码路径和有界观察结果；needs_validation 必须说明确切的缺失事实且不评严重性；rejected 保存已被证伪的候选。最终报告应来自独立复核后的结构化记录。

## 可以先借鉴什么

以下是 AI 据材料归纳的待实践建议：用一条已有候选检查“谁提供低信任输入、跨过什么边界、影响谁、当前源码有什么阻止措施、实际观察到了什么”。把不可见的部署前提单独列出，再交给独立检查者尝试推翻。评估整个审计时，同时查看覆盖台账和未检查范围。

## 还缺什么

本库未在真实目标上运行该技能，没有误报率、漏报率、执行成本或沙箱兼容性数据。新会话和 schema 校验都不能单独保证结论正确；没有发现漏洞不能表示目标安全。
