# 代码变更后，怎样选择回归测试，又说明没测到什么？

[← 问题索引](README.md) · [验证技能](../tags/验证技能.md)

检索词：回归范围、变更影响、必选测试、条件测试、覆盖缺口、剩余风险。

## 先看什么

[R0020：awesome-qa-skills](../resources/R0020/README.md)，先读 regression-test-selection 的 SKILL.md 和配套主提示词。它要求结合 diff、覆盖映射、历史失败、执行成本与依赖，分别解释必选、条件执行和可跳过项。

再对照 [R0010：AI 构建 E2E 测试体系](../resources/R0010/README.md) 的用户旅程与组合矩阵，明确“选了某个用例”与“每种框架、数据库组合都跑过”是不同结论。

补充：[R0033：How the Claude Code team thinks about verification](../resources/R0033/README.md)：按代价与证据强度在 E2E、属性测试、差分测试之间取舍；提醒 flaky 与慢测试会让 Agent 重跑而不是修代码。

## 可以先试什么

以下是 AI 据材料归纳的待实践建议：选一个真实变更，列出受影响行为和现有测试 ID，给每个选入与排除决定补上依据；高风险却没有测试映射的区域单独记录缺口，安排针对性补测或探索。报告保留实际执行结果，不把待执行清单写成已通过。

## 还缺什么

本库尚无用户项目的 diff、覆盖映射、耗时或失败历史，无法直接给出最小充分回归集。用例选择合理，也不能独立证明断言有效或遗漏风险已消除。
