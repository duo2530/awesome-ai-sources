## 一句话说明

先把验证瓶颈变成可复用工具，再用分阶段证据、停止条件和小步反馈建立可以信任的 Agent 自动化闭环。

## AI 摘要与要点

作者用早餐工厂和管理杠杆解释 Agent 工作流：并行写代码并不能消除验证瓶颈，工具和质量机制才可能减少人工接力。

- **先提供真实反馈**：让 Agent 运行应用、复现问题、采集性能与界面证据，再讨论自动化。
- **失败变成基础设施**：将反复出现的错误写进技能、脚本、检查或架构约束；机械步骤优先交给确定性工具。
- **每个阶段允许停下**：将反馈分诊、复现、修复与验证分开；非缺陷、无法复现、风险过大都是有效结果。
- **留下可审阅证据**：失败/通过对照、截图、视频、性能记录与决策日志，帮助人判断修对了什么。
- **小步迁移而非大批灌入**：StyleX 迁移案例中，已捕获状态视觉一致仍遗漏实际使用问题；后来改成逐组件迁移并检查跨代码依赖。

例子是作者对自己工作流的描述，摘要不表示本库已经部署对应系统。
