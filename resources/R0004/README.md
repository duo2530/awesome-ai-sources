## 一句话说明

把应用验证当作工程基础设施：用可重复的 CLI 操作和检查应用，以 Feature Map 说明功能入口，持续维护后再扩展并行开发与自动反馈。

## AI 摘要与要点

作者以 pstack 的验证技能为主线，强调 Agent 能直接操作应用、获取运行反馈并验证改动，才能减少人工逐项验收的瓶颈。关键不止是写一份技能说明，而是提供可靠工具、可复现环境和共享功能知识。

| 核心部分 | 文中做法 | 为什么值得关注 |
|---|---|---|
| 验证工具 | 将导航、交互、快照、截图、日志、性能追踪等封装为小型 CLI | 避免每次临时写一次性操作脚本，方便复用与测试 |
| 开发环境 | 准备测试数据、认证、测试用户及一致的启动方式 | 让 Agent 能真正运行应用，而非停在阅读代码 |
| Feature Map | 总览链接到每个功能的用户路径、控制命令与易错点 | 应用变复杂后仍能找到入口，减少重复探索 |
| 持续维护 | 随应用变化更新验证技能、控制工具与功能地图 | 避免共享文档和真实界面逐渐失配 |
| 扩展工作流 | 在验证可靠后再尝试云端并行、性能样本验证、反馈复现 | 自动化依赖前面的验证能力，不是先增加 Agent 数量 |

文中建议 CLI 支持可组合命令、清晰错误、渐进式帮助、机器可读输出；可能产生破坏性副作用的命令应有 dry-run。上述为作者建议，不表示本库已部署这些工具。
