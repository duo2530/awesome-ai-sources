## 一句话说明

通过验证工具、技能、代码结构与静态检查积累对 Agent 的信任，再扩展并行和事件驱动工作，而不是先追求 PR 数量。

## AI 摘要与要点

本页仅根据用户提供的英语 SRT 字幕整理，未观看视频或核对演示画面。字幕覆盖 00:00:01,340—00:38:01,280，共 629 条；只能说明已有字幕的范围，不能证明视频完整时长。

- **信任来自环境而非 Agent 数量**：先让 Agent 得到应用运行反馈与验证证据，减少人持续纠正的负担。
- **控制工具配合功能地图**：重复使用 CLI 控制应用，并用 Feature Map 告诉 Agent 功能是什么、用户怎样到达。
- **功能正确不等于整体质量**：还要看性能、代码模式与工程工作方式，不能只证明某个按钮能操作。
- **让正确路径更容易**：代码会成为后续 Agent 的样例；用架构和静态分析限制错误，再叠加规则、评审工具与技能。
- **持续清理技术债**：防止临时绕过方案被不断模仿，观察重复纠正是否能变成 lint、类型或依赖边界。
- **外层接收事件，内层执行**：视频后段讨论从反馈或告警触发任务，并复用已有验证能力。
