## 一句话说明

以复述、历史调研和使用方式建立共同理解，再用可运行原型与接口草图比较方案，最后拆成小而可验证的执行任务。

## AI 摘要与要点

Pt. 1 解决“做完如何验证”，本篇继续讨论“该做什么、怎样设计”。作者反对仅凭抽象计划获得安心，主张用实际材料与原型消除不确定性。

- **先复述问题**：让 Agent 用自己的话解释输入，尽早发现误解，避免将人的猜测直接灌成结论。
- **理解机制与动机**：通过代码、历史决策与相关记录分别调查怎么运行、为什么这样设计，并复用已有会话背景。
- **从使用方式倒推设计**：先写面向使用者的教程或 README，再确定接口与实现；区分教程、操作指南、参考和解释四种文档用途。
- **比较可运行方案**：用原型、截图与测量回答开放问题，不只接受第一个设计，也不在没有证据时不断增加抽象风险。
- **设计错误时舍弃**：先做接口与类型草图，实施时若暴露反复绕过设计的需求，重新审视架构。
- **执行计划围绕证据**：设计确定后再拆小 PR，每项列验证与实际运行要求；小 PR 本身不自动保证结果正确。
