## 一句话说明

用七部分项目说明帮助 Agent 理解业务、遵守修改边界、定位代码、排查日志，并按需查资料和执行验证；保留精简入口而非把所有项目内容堆进一个文件。

## AI 摘要：七部分分别负责什么

以下根据截图归纳，属于 AI 整理，不是完整配置转录。

| 部分 | 解决的疑问 | 为自己的项目填写什么 |
|---|---|---|
| 项目介绍 | 项目服务谁，业务术语是什么意思？ | 业务背景、核心功能关系和容易误解的术语 |
| 编码原则 | 遇到模糊目标如何判断，允许改多大范围？ | 需求确认方式、决策原则、修改边界 |
| 技术栈 | 当前实现受哪些条件约束？ | 实际语言、框架、中间件与版本及兼容要求 |
| 工程架构 | 改动放哪里，模块之间如何协作？ | 模块位置、领域职责、调用与依赖约束 |
| 系统日志 | 出问题时去哪里找证据？ | 日志框架、配置、排查入口和定位工具 |
| 关键文件 | 哪种任务应该读取哪个文件？ | 文件入口及触发条件，避免平铺所有资料 |
| 验证方式 | 做完之后怎样证明改动正确？ | 项目适用的单元测试、Mock 约定及验证方式 |
