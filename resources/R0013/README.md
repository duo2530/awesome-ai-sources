## 一句话说明

并行 Agent 的瓶颈会从单任务执行逐步转向协调；先建立共享记忆、可观察队列和治理边界，再按真实负担自动化会话拆解、派发、巡检、验收与排序。

## AI 摘要与要点

文章用 Kiro Crew 的建设经历描述五个演进阶段，重点不是追求会话数量，而是识别每阶段仍由人承担的协调工作。

| 阶段 | 增加的能力 | 下一处瓶颈 |
|---|---|---|
| 单会话 | 一个人驱动一个 Agent | 每步都等待人的注意力 |
| 多标签页 | 并行推进几个任务 | 重复解释背景，人记住各会话状态 |
| 记忆、面板、定时与工作流 | 会话带背景启动，可跟踪并自动串起部分步骤 | 人仍阅读更新并决定下一步 |
| 队列式 Agent 流水线 | 分诊、实现、审查、合并各取自己的队列 | 流程形状固定，方案失效仍需人重排 |
| 早期 Crew Mode | 协调 Agent 跨会话拆解、派发、巡检、验收和排序 | 协调者自身也受上下文、能力与成本限制 |

文中称一周合并 1,000 个 PR 来自队列流水线与早期 Crew Mode 的组合，不是仅靠一个成熟的万能管理 Agent。团队也在探索多个协调角色与 crew 之间的协作。

作者重点列出四类治理问题：任务归属与决策记录要持久化；记忆有项目与可见范围；权限由宿主执行；动作、审批与拒绝留在 Agent 不能修改的审计记录中。大规模协调还带来额外成本，需要逐任务归集、减少重复上下文并将确定步骤交给脚本。

建议路径是从当前最费人的一项重复协调任务入手，先做小改进；不要直接从“多开会话”跳到高自治编排。
