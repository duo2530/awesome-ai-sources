## 一句话说明

让 LLM 持续维护一套与原始资料分离、相互链接的 Markdown 知识页面，把新增资料和有价值的问答逐步积累成可复用的理解。

## AI 摘要与要点

本文是一份模式说明，强调知识加工的持久积累，不是提供可直接运行的项目。

| 环节 | 作者提出的做法 | 对本库的参考价值（本库判断） |
|---|---|---|
| 三层组织 | 原始资料保留不改；Wiki 存摘要、实体、概念与比较；规则文件约定结构和维护行为 | 对应正文、整理页、AGENTS.md 与流程，不必为了命名统一立即改目录 |
| 收录 Ingest | 读新来源，更新已有页面、交叉引用、综合观点及矛盾，并记录日志 | 新文章除了新增摘要，也应修订已有问题答案；不能只追加链接 |
| 查询 Query | 读相关页面，带引用回答；有价值的比较和分析可回存成页面 | 问答产生的新理解也可保留，需区分 AI 归纳与实际验证 |
| 巡检 Lint | 检查矛盾、过时陈述、孤立页面、缺失关系与知识空白 | 确定性的结构检查与需要语义审阅的内容巡检分别处理 |
| 导航与历史 | index 按内容找页面，log 按时间记录收录、查询与巡检 | Git 历史能辅助追踪，但不等于已经有面向知识维护的查询日志 |
| 工具选择 | 小规模先用索引，搜索、图片、展示与 Obsidian 插件按需选择 | 工具是可选项，不把图视图或向量检索当作采用模式的前提 |

## 适用边界与查漏补缺

- 这是抽象模式与个人经验，不是带测试、依赖和部署步骤的完整实现；没有由本库重放的效果评测。
- 对 RAG 每次重新综合的批评是作者对常见用法的概括，不意味着所有 RAG 系统没有记忆或不能积累；两种方式可以组合。
- LLM 可能漏更新、产生矛盾、误改综合页；维护成本仍包括推理、审阅、修正与工具运行，不能把作者的强表述当可靠性保证。
- 图中有连接、结构检查通过或多个页面重复同一结论，都不独立证明结论正确；需回到原始证据并保留分歧。
- 原文建议 AI 全权维护生成层；本库仍保留用户笔记与实践记录，不据此允许 AI 覆盖用户内容。
- 本轮未安装 qmd、Obsidian 插件或 Marp，未执行原文示例，未新增自动采集、语义巡检或问答自动回存工作流。
- 当前只保存此文及关联索引；未完整检查账号、个人履历或所有外链，未见文件中单独声明许可证，不将本库 MIT 扩展到第三方原文。
